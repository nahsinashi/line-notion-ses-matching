# LINE配信候補ピックアップ＆配信コマンド

Notionの案件・要員データベースからスコアリングにより配信候補をピックアップし、ユーザー承認後にLINE配信を実行するコマンド。

## 実行手順

### Step 1: 配信候補のピックアップ

以下のコマンドを実行して配信候補を取得する:

```bash
cd C:\Users\user\claude-workspace\line-notion-matching\broadcast-skill
python broadcast.py --top 3 --type all
```

- `--top N`: 案件・要員それぞれ上位N件をピックアップ（デフォルト: 3）
- `--type all|cases|staff`: 対象タイプを指定（デフォルト: all）
- `--threshold N`: 最低スコア足切り（デフォルト: 0）
- `--include-sent`: 配信済み（7日以内）も含める

**環境変数が必要:**
- `NOTION_API_KEY`: Notion APIキー
- `NOTION_DB_CASES`: 案件DBのID（省略時はデフォルト値を使用）
- `NOTION_DB_STAFF`: 要員DBのID（省略時はデフォルト値を使用）

### Step 2: 結果をユーザーに提示

ピックアップ結果をわかりやすく整形して表示する。以下の情報を含めること:

**表示項目（案件・要員共通）:**
- タイトル（案件名 / 要員名）
- スコア（総合点/100）
- 内訳（各軸のスコア）
- サマリー（**必ず全文表示。省略・要約は禁止**）
- 元企業名（案件元企業 / 要員元企業）

**上記以外の項目（単価、スキル、リモート、年齢、SS有無など）はサマリー内に含まれるため個別表示しない。**

表示フォーマット:
```
━━━━━━━━━━━━━━━━━━
【案件1】案件名 — スコア: XX/100
内訳: 単価XX/30 言語XX/20 鮮度XX/25 リモートXX/25
元企業: XXXXX
━━━━━━━━━━━━━━━━━━
（サマリー全文をそのまま表示）
```

### Step 3: ユーザーの承認を得る

ユーザーに以下を確認する:
1. 配信する案件・要員の選択（番号指定 or 全件）
2. テストモードの有無（管理者のみに送信するか）
3. 配信実行の最終確認

**必ずユーザーの明示的な承認を得てから Step 4 に進むこと。**

### Step 4: 配信実行

承認後、以下のコマンドで配信を実行する:

```bash
cd C:\Users\user\claude-workspace\line-notion-matching\broadcast-skill
python send_broadcast.py --cases <page_id1> <page_id2> --staff <page_id3> <page_id4>
```

- `--cases`: 配信する案件のNotionページID（スペース区切り）
- `--staff`: 配信する要員のNotionページID（スペース区切り）
- `--test`: テストモード（管理者のみに送信）

### Step 5: 結果報告

配信結果をユーザーに報告する:
- 成功/失敗のステータス
- 配信された案件・要員の件数
- エラーがあった場合はエラー内容

## スコアリング基準

### 案件（100点満点）
- **単価 (30点)**: 65-80万がスイートスポット
- **言語 (20点)**: PHP/Java/JS/TSが最高、Python/C#が次点
- **鮮度 (25点)**: 登録3日以内が最高点
- **リモート (25点)**: フルリモートが最高点

### 要員（100点満点）
- **年齢 (25点)**: 28-32歳がスイートスポット
- **単価 (25点)**: 65-75万がスイートスポット
- **鮮度 (25点)**: 登録3日以内が最高点
- **言語 (15点)**: PHP/Java/JS/TSが最高
- **スキルシート (10点)**: 有りで10点

## 注意事項
- 7日以内に配信済みの案件・要員は自動的に除外される
- 同名の重複レコードも自動的に除外される
- config.json にGAS WebApp URLとブロードキャストトークンの設定が必要
